P0 — Critical Bugs

2-3 hours · Engine race condition, IndexedDB connection leaks
P0
P0
useUciEngine singleton race condition
src/engine/useUciEngine.ts:9-57 Concurrency Risk: OOM from duplicate Stockfish instances

Multiple components mounting simultaneously (e.g. Analysis + Play + PuzzleList) can all see singletonEngine === null and create duplicate engine instances, each spawning separate Web Workers (~5-10MB each).

Files
  • src/engine/useUciEngine.ts
  • src/engine/__tests__/useUciEngine.test.tsx
  1. Add promise guard: module-level initPromise: Promise<UciEngine> | null = null
  2. Refactor getOrCreate(): if initPromise exists, await it — never call UciEngine.create() twice
  3. Test: spawn 5 concurrent useUciEngine hooks with Promise.all, verify single engine created
  4. Verify refCount cleanup: engine shuts down when last component unmounts
✓ Acceptance: No duplicate Stockfish instances under concurrent component mount. All 320+ tests pass.
P0
IndexedDB connection management leaks
src/data/studyFolders.ts src/data/userOpenings.ts Risk: "Database closed" errors, data loss

Every function opens a DB connection and calls db.close() in finally. The idb library manages connection pooling internally — manual close() breaks other in-flight operations.

Files
  • src/data/studyFolders.ts
  • src/data/userOpenings.ts
  • src/data/__tests__/studyFolders.test.ts
  • src/data/__tests__/userOpenings.test.ts
  1. Remove all db.close() calls from both files
  2. Remove finally { db.close() } blocks (the try can become function body)
  3. Add test: concurrent createFolder + listFolders — no errors
  4. Verify deleteDB in test beforeEach still works for isolation
✓ Acceptance: No manual connection management. Concurrent operations succeed without errors.
