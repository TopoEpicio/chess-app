Fase G Backend — ottimizzare _build_descendant_counts 1 ora

backend rischio basso

File: backend/app/routers/openings.py, funzione _build_descendant_counts (righe 13-35)

Problema: db.query(RepertoireNode).all() carica l'intera tabella in memoria anche quando servono solo pochi nodi radice. Per database con decine di migliaia di nodi, spreco di memoria e I/O.

Soluzione: Sostituire con query batch che carica solo i figli dei nodi non ancora visitati:

def _build_descendant_counts(db: Session, roots: set[int]) -> dict[int, int]:
    # Carica solo i nodi rilevanti (figli dei roots o dei loro discendenti)
    # invece di caricare l'intera tabella
    children_of: dict[int, list[int]] = defaultdict(list)
    counts: dict[int, int] = {}
    to_visit: set[int] = set(roots)

    while to_visit:
        batch = db.query(RepertoireNode.id, RepertoireNode.parent_id) \
                 .filter(RepertoireNode.parent_id.in_(to_visit)).all()
        to_visit.clear()
        for node_id, parent_id in batch:
            children_of[parent_id].append(node_id)
            to_visit.add(node_id)

    for root in roots:
        total = 0
        stack = list(children_of.get(root, []))
        visited_bfs = {root}
        while stack:
            nid = stack.pop()
            if nid in visited_bfs: continue
            visited_bfs.add(nid)
            total += 1
            stack.extend(c for c in children_of.get(nid, []) if c not in visited_bfs)
        counts[root] = total

    return counts
Vantaggio: Per un albero con N nodi totali e R roots, la query carica al massimo N righe (come prima) ma le carica a lotti (~1 query per livello di profondità). Per alberi piccoli o pochi roots, il numero di righe caricate è molto minore di N.

Fase 1 Fix worker.ts — WASM factory + command queue 2 ore

frontend rischio medio ⚠ non testato in produzione

File: frontend/src/engine/worker.ts, ramo WASM (righe 35-78)

1.1 Catturare factory return value

Problema: StockfishFactory(opts) (riga 45) viene chiamato ma il return value viene scartato. Il codice accede a opts.postMessage che, sebbene funzioni per side-effect di Emscripten (che muta opts), è fragile e non corrisponde alle type declaration.

Fix:

StockfishFactory(opts)
const engine = StockfishFactory(opts)

Conseguenza: Tutte le occorrenze di opts.postMessage, opts.terminate, opts.addMessageListener devono essere sostituite con engine.*.

1.2 Rimuovere parametri superflui

locateFile non serve perché i file sono nella root di public/ e serviti da nginx con path /stockfish.wasm (predefinito di Emscripten).

const opts: Record<string, unknown> = { locateFile: (path: string) => `/${path}` }
StockfishFactory(opts)
const engine = StockfishFactory()
Da verificare durante l'implementazione: Assicurarsi che StockfishFactory() senza parametri carichi stockfish.wasm da /stockfish.wasm. Il path predefinito di Emscripten è derivato dallo script path (stockfish.js → /stockfish.wasm).

1.3 Fix command queue race condition

Problema: firstOutputReceived viene impostato su true solo al primo messaggio ricevuto via addMessageListener. Se Stockfish non produce output prima di ricevere comandi, la coda non viene mai svuotata.

Soluzione: Usare la Promise engine.ready (esposta da Emscripten) come trigger primario per svuotare la coda, con fallback sul primo messaggio:

let firstOutputFlushed = false

function flushCmdQueue() {
  if (firstOutputFlushed) return
  firstOutputFlushed = true
  for (const cmd of cmdQueue) {
    engine.postMessage(cmd)
  }
  cmdQueue.length = 0
}

// Trigger primario: engine.ready (Promise Emscripten)
engine.ready?.then(flushCmdQueue)

// Fallback: primo messaggio in arrivo da Stockfish
engine.addMessageListener(event => {
  flushCmdQueue()
  // ... process message ...
})

1.4 Schema finale del ramo WASM

const StockfishFactory = window.Stockfish
if (typeof StockfishFactory !== 'function') {
  throw new Error('window.Stockfish is not available.')
}

const engine = StockfishFactory()
const cmdQueue: string[] = []
let firstOutputFlushed = false

function flushCmdQueue() { /* come sopra */ }
engine.ready?.then(flushCmdQueue)
engine.addMessageListener(event => {
  flushCmdQueue()
  const cleaned = event.replace(/^Thread \d+: /, '')
  engineWorker.listen(cleaned)
})

const engineWorker: EngineWorker = {
  isReady: false,
  uci: (command: string) => {
    if (firstOutputFlushed) {
      engine.postMessage(command)
    } else {
      cmdQueue.push(command)
    }
  },
  listen: () => {},
  terminate: () => engine.terminate?.(),
}

Fase 4 Integrare engineConfig in useUciEngine 1.5 ore

frontend rischio medio

File: frontend/src/engine/useUciEngine.ts

4.1 Modificare singleton pattern

Il singleton enginePromise deve tenere traccia delle opzioni e ricrearsi quando cambiano:

let enginePromise: Promise<UciEngine> | null = null
let currentOptions: UciEngineOptions | null = null

async function getOrCreate(options: UciEngineOptions): Promise<UciEngine> {
  // Se le opzioni sono cambiate, riavvia l'engine
  if (enginePromise && currentOptions && !shallowEqual(currentOptions, options)) {
    const engine = await enginePromise
    engine.shutdown()
    enginePromise = null
  }

  if (!enginePromise) {
    currentOptions = options
    enginePromise = UciEngine.create('Stockfish', 'wasm', options)
  }
  return enginePromise
}

// Utility per confronto shallow
function shallowEqual(a: Record<string, unknown>, b: Record<string, unknown>): boolean {
  for (const k of Object.keys(a)) { if (a[k] !== b[k]) return false }
  return Object.keys(a).length === Object.keys(b).length
}

4.2 Leggere engineStore nell'hook

export function useUciEngine() {
  const { hash, threads, multiPv } = useEngineConfig()
  // ... stato locale ...

  useEffect(() => {
    let cancelled = false
    refCount++

    getOrCreate({ hashSize: hash, threads, multiPv })
      .then(engine => {
        if (cancelled) return
        engineRef.current = engine
        setReady(engine.getIsReady())
      })
      .catch(err => { if (!cancelled) setError(String(err)) })

    return () => {
      cancelled = true
      refCount--
      if (refCount <= 0) destroySingleton()
    }
  }, [hash, threads, multiPv]) // Re-execute quando opzioni cambiano

  // ... resto invariato ...
}
Impatto: Il riavvio dell'engine è un'operazione asincrona (~100-500ms per il WASM init). Durante il riavvio, ready diventa false e poi true. Le chiamate in sospeso (analyze, deepAnalyze) falliranno silenziosamente perché engineRef.current viene aggiornato solo dopo il .then().

Fase 5 destroySingleton — cleanup pulito 30 min

frontend rischio basso

File: frontend/src/engine/useUciEngine.ts, righe 23-27

Problema: La funzione ha corpo vuoto. I worker engine non vengono mai terminati quando tutti i consumer smontano.

Implementazione:

function destroySingleton(): void {
  const p = enginePromise
  enginePromise = null
  currentOptions = null
  p?.then(engine => engine.shutdown())
}
Nota tecnica: Emscripten con pthreads (B = PThread) condivide stato globale. shutdown() chiama B.bc() che termina TUTTI i worker pthread. Dato che abbiamo un singolo engine singleton, questo è sicuro. Se in futuro servissero engine multipli concurrently, bisognerà isolare ogni engine in un Web Worker separato (Fase 7).

Motivazione

  • Isolare Stockfish in un Web Worker evita di bloccare la UI durante l'inizializzazione WASM

Implementazione

Nuovo file: frontend/src/engine/stockfish.worker.ts

// Carica stockfish.js all'interno del worker
importScripts('/stockfish.js')

let engine: ReturnType<Window['Stockfish']> | null = null

self.onmessage = (e: MessageEvent) => {
  const msg = e.data as { cmd: string; args?: string[] }

  if (msg.cmd === 'init') {
    engine = window.Stockfish?.()
    engine?.addMessageListener(output => {
      self.postMessage({ type: 'output', data: output })
    })
    engine?.ready?.then(() => {
      self.postMessage({ type: 'ready' })
    })
    return
  }

  if (msg.cmd === 'uci' && engine) {
    engine.postMessage(msg.args?.[0] ?? '')
  }
}

Modificare worker.ts — ramo WASM

Invece di eseguire Stockfish sul main thread, creare un Web Worker:

const worker = new Worker(
  new URL('./stockfish.worker.ts', import.meta.url),
  { type: 'module' },
)

let ready = false
const queue: string[] = []

worker.onmessage = (e) => {
  if (e.data.type === 'ready') {
    ready = true
    for (const cmd of queue) worker.postMessage({ cmd: 'uci', args: [cmd] })
    queue.length = 0
  }
  if (e.data.type === 'output') {
    engineWorker.listen(e.data.data)
  }
}

worker.postMessage({ cmd: 'init' })
